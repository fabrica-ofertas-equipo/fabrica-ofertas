## 1. Qué es
Una app **local** (solo `127.0.0.1`), sin dependencias externas: servidor en **biblioteca estándar de Python** + **JavaScript puro (módulos ES)** + CSS propio. Sin npm, sin CDN, sin fuentes remotas: funciona sin internet. Arranque: `.venv/bin/python -m dashboard [--puerto 8765] [--raiz RUTA] [--abrir]`; imprime `http://127.0.0.1:8765/#t=<token>`. **Los datos que no existan aún (el motor se está construyendo) se muestran como estado vacío explícito**, nunca como cero ni como dato inventado. La oferta `ofertas/_ejemplo` (demo, es-ES) se lista con `demo: true` para poder ver todas las pantallas llenas.

## 5. Frontend: módulos y firmas fijadas
- **`api.js`**: `api.get(ruta, params?) → Promise<datos>` (lanza `ErrorApi{codigo,mensaje}`; maneja `vacio`), `api.post(ruta, cuerpo)`, `api.conectarEventos(onEvento) → {cerrar()}` (SSE con reintento y caída a sondeo cada 5 s), `api.token()`. El token sale del fragmento `#t=` de la URL, se guarda en `sessionStorage` y se quita de la barra.
- **`ui.js`** (todo texto de datos entra por `textContent`/`createTextNode`; **prohibido `innerHTML` con datos**): `el(tag, attrs?, ...hijos) → Element`, `chip(texto, tono?)` (tonos: `ok|aviso|error|info|neutro`), `estadoChip(estado)` (mapea `aprobado, en_QA, en_progreso, pendiente, bloqueado, escalado, obsoleta`), `tarjeta({titulo, valor, detalle?, tono?, tendencia?})`, `seccion(titulo, cuerpo, {acciones?, ayuda?})`, `tabla({columnas:[{clave, titulo, ancho?, formato?, ordenable?}], filas, filtro?, vacio?, alClick?})`, `tabs([{id, titulo, render}], activo?)`, `visorJson(obj, {colapsado?})`, `visorTexto(texto, {tipo})`, `vacio(texto, {pista?})`, `cargando()`, `errorBox(err)`, `copiar(texto)`, `toast(texto, tono?)`, `modal({titulo, cuerpo, acciones})`, `fmt.fecha(iso)`, `fmt.relativo(iso)`, `fmt.dinero(monto, moneda)`, `fmt.bytes(n)`, `fmt.pct(bp)`.
- **`estado.js`**: estado global mínimo (`ofertaActiva`, `tema`, `sidebarColapsada`, `conectado`) con `suscribir(fn)`.
- **`app.js`**: router por hash, montaje del sidebar/topbar, ciclo de vida de páginas, suscripción a SSE y notificación de cambios a la página visible (con rebote de 400 ms).
- **Página** (`pages/<ruta>.js`): `export const meta = {ruta, titulo, grupo, icono?}; export async function render(ctx) → Element; export function alCambio(ctx, evento) {}` (opcional; si falta, el router re-renderiza con rebote). `ctx = {api, ui, fmt, params, estado, ruta}`. `ctx.params.id` para `#/oferta/<id>`.
- **Diseño** (minimalista pero denso en información): sidebar 232 px colapsable a 56 px; tipografía de sistema; una sola paleta neutra + un acento; tonos semánticos solo para estado; tablas densas con cabecera fija, filas de 32-36 px; tarjetas de métricas arriba y detalle abajo; **clave/valor y tablas antes que gráficos**; gráficos solo SVG propio sin librerías (sparklines y barras); tema claro/oscuro con `prefers-color-scheme` + conmutador; foco visible; contraste AA; responsive (sidebar se oculta < 900 px). Cada pantalla muestra siempre: qué es, de qué archivo sale (`fuente`), cuándo se leyó y un estado vacío útil que dice qué hay que correr para llenarla (con el comando exacto copiable).
- **Verificación visual**: levanta el servidor en un puerto local y saca capturas con Chrome sin pantalla SOLO contra `127.0.0.1` (`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --screenshot=RUTA --window-size=1440,900 URL`); revisa que no haya texto cortado, tablas desbordadas ni pantallas vacías sin explicación. Nunca abras una URL que no sea `127.0.0.1`.

## 7. Seguridad (no negociable; hubo hallazgos reales de este tipo en el barrido)
1. Escucha solo en `127.0.0.1`; rechaza cualquier `Host` que no sea `127.0.0.1:<puerto>` o `localhost:<puerto>` (anti DNS-rebinding); `POST` exige `Origin` propio y `X-Panel-Token` (token aleatorio de 32 bytes por arranque, comparado en tiempo constante).
2. **Confinamiento de rutas**: toda lectura pasa por un único resolvedor que normaliza, rechaza `..`, rutas absolutas, enlaces simbólicos que escapen de la raíz y archivos tipo `.env`, `*.pem`, `*.key`, `secretos*`; tope de tamaño; nunca sigue enlaces hacia fuera.
3. Texto de datos (títulos de anuncios, nombres de página, contenido de archivos) es **no confiable**: se escapa siempre; el visor de HTML de la landing va en `iframe sandbox="allow-scripts"` (sin `allow-same-origin`) servido con CSP; nunca se interpreta Markdown a HTML con datos externos.
4. Sin `shell=True`, sin `eval`/`exec`/`pickle`; `yaml.safe_load`; JSON estricto (sin NaN/Infinity); errores sin trazas ni rutas absolutas hacia el cliente.
5. No imprime ni expone variables de entorno, claves, tokens; no las pasa a procesos hijos.
6. Las pruebas no abren sockets (salvo un servidor en `127.0.0.1` con puerto efímero si es imprescindible) y **no tocan `empresa/` ni `ofertas/` reales**: usan `--raiz` temporal con fixtures.
7. Todo lo que el panel escribe está en `empresa/panel/` o es `empresa/PAUSA`; escritura atómica; no sobrescribe.

**API de servicio** (la usan Workers y `engine.orq`; es otra cosa que la API local del panel): `dashboard/api.py`, aplicación WSGI de la biblioteca estándar que monta los controladores de `datos` (`manejar_ingesta_evento(cuerpo, cabeceras, conn, ahora) → (status, dict)` y los de entrega/Stripe): `POST /ingesta/evento`, `POST /ingesta/entrega`, `POST /webhooks/stripe` (firma propia de Stripe), `POST /ordenes` e `POST /ingresar` (los que `engine.orq` consumirá; formato exacto en el plan y en `departamentos/13`), `GET /estado` **firmado** y `GET /salud` mínimo. Autenticación interna: `X-Fabrica-Ts` (UTC ISO con Z) y `X-Fabrica-Firma: hmac-sha256=<hex>` = HMAC-SHA256 con `INGEST_HMAC_SECRET` (comparación en tiempo constante); marcas fuera de `ingesta.tolerancia_seg` → 400, firma inválida → 401, `event_id` repetido con otro contenido → 409, cuerpo sobre `ingesta.cuerpo_max_bytes` rechazado, idéntico → 200 `duplicado`. **Prefijo de contexto (revisión de seguridad m-4, 2026-11-06):** el mensaje firmado es `ts + "." + cuerpo_exacto` en `POST /ingesta/evento` y `POST /ingesta/entrega` (Workers → API, docs/06 §4.7 tal cual, SIN cambio) y `contexto + "." + ts + "." + cuerpo_exacto` en lo que firma el dashboard: `GET /estado` (petición `req`, cuerpo vacío; la RESPUESTA lleva `X-Fabrica-Ts` y `X-Fabrica-Firma` con contexto `resp`), `POST /ordenes` (`req`) y `POST /ingresar` (`req`). Así una firma de respuesta nunca autentica una petición. Ejemplo exacto (secreto `secreto-de-ejemplo`, `ts` = `2026-11-09T12:00:00Z`, cuerpo `{"etapa":"D1","oferta_id":"OF-202611-01"}`): sin contexto → `hmac-sha256=d37d04267ad3153664bc993ac36a40ea09d854920339d5f6674d70b2d0594749`; contexto `req` (mensaje `req.2026-11-09T12:00:00Z.{"etapa":"D1","oferta_id":"OF-202611-01"}`) → `hmac-sha256=74cc8e5c10f5c6f337b5dba9ecba66c0a0fe4ac9c5d0218b1265d5a7e74d455e`; contexto `resp` → `hmac-sha256=a73d537ebdb37bc0380e8bbadd54be3e7bc12c45b4114661c48e243598f282de`. En Python: `hmac.new(secreto, b"req." + ts.encode() + b"." + cuerpo, hashlib.sha256).hexdigest()` (`dashboard.api.firmar(secreto, cuerpo, ts, "req")`). Orden de comprobaciones: `Content-Length` estricto (solo dígitos ASCII; 411/400/413) → marcas presentes (401) → `ts` válido y en tolerancia (400) → lectura del cuerpo con plazo total → firma (401) → JSON y forma (400) → efecto. Errores de configuración (sin secreto o sin `ingesta.*`): `500 {"ok": false, "motivo": "configuracion_incompleta"}` sin nombres de variables ni archivos (el detalle va al log). `POST /ingesta/evento` con `consentimiento: false` responde 200 y el evento queda SIN ATRIBUCIÓN (`atribuible: false`; no se rechaza). `POST /ingresar` delega en `engine.orq.ingresar_desde_cuerpo` (cuerpo JSON con exactamente `oferta_id`, `etapa`, `archivos[{ruta, contenido_b64}]`; `ValidacionError`/uso → 400, bloqueado → 409, parámetro `ingesta.cuerpo_max_bytes` ausente → 500 genérico). Entrada propia: `python -m dashboard.api`; el panel local (`python -m dashboard`) y esta API son dos aplicaciones WSGI distintas que comparten lectores y seguridad. Si el plan y este contrato difieren, manda el plan; anótalo como PEDIDO.
