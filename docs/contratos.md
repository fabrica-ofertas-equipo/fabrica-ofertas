Si choca con `docs/_backbone.md` (v2.2), manda el backbone. Ejecutable: `.venv/bin/python -m scripts.validar_esquemas` (esquemas + ejemplos + `ofertas/_ejemplo/` con reglas cruzadas). Pruebas: `.venv/bin/python -m unittest discover -s tests/contratos -t .`. Parámetros fail-closed: `python -m scripts.validar_esquemas parametros empresa/parametros.yaml --operacion runner_vivo` (salida 5 si falta algo).

**Principios.** (1) Un artefacto = un esquema = un productor; los demás leen. (2) Dinero = entero en unidad menor + moneda ISO 4217; ratios y tasas = cadena decimal o puntos básicos; **ningún `float`** (el validador lo rechaza en esquema y en datos). (3) Tiempo UTC con `Z`. (4) IDs con patrón anclado (`comunes.schema.json`). (5) Enumerados (veredicto QA, severidad, nivel, gate, tipo de evidencia, macro-nicho, motivo de rechazo) definidos **una sola vez** en `comunes.schema.json`. (6) `additionalProperties: false` en todo artefacto. (7) Todo presupuesto, tope y umbral es **paramétrico** (`limites.yaml` o `parametros.yaml`); si falta un dato de límites, **nada gasta ni activa** (fail-closed, código 5).

Decisiones de forma: (a) `ids_meta` usa `adset_ids[]` (plural, igual que `campana.ids_meta`; un conjunto = lista de 1) en vez del `adset_id` del plan; (b) `preflight` exige `P01…P24` y admite `P25` (categoría especial = dictamen de X1), obligatorio si `special_ad_categories` no está vacío; (c) `ledger` guarda importes ≥ 0 con `sentido` aparte y hace upsert por `clave_natural`; `importe_base` y `tipo_cambio_id` van juntos; (d) `decision_id = sha256 canónico de {oferta_id, objeto_id, lectura_ts}`; (e) `postmortem.retraso_clic_compra{n_compras, mediana_h, p90_h, fuente}` es **obligatorio** y, con 0 compras, `mediana_h/p90_h` son `null` y `fuente = no_medible`; (f) `traspaso.lanzamiento_estable` solo con `ventana_h = 72`, 0 anomalías y 0 rechazos; (g) estados de Meta (`effective_status`, aprendizaje) se guardan tal cual (`^[A-Z_]+$`), sin enumerarlos: la enumeración vigente es `[VERIFICAR]`.

**Hashes y sellos.** JSON canónico = claves ordenadas, sin espacios, UTF-8 sin `float` (convenciones 5). Hash de un archivo: JSON/YAML por su forma canónica (**claves duplicadas = error**), texto normalizado a NFC y `\n`, el resto por bytes; los `.html/.js/.css/.svg` de `05-landing/sitio/` **por bytes** (el sello cubre lo que se sirve) y `landing.desplegar` vuelve a hashear justo antes de subir; de una carpeta, el hash del mapa `ruta -> hash`. `estado.etapas.<E>.hash_salida` = hash del mapa de los **archivos sellados** de la etapa: M1 `mercado.json`; D1 `candidatos.json`; D2 `validacion.json`; D3 `oferta.json` + `economia.json`; D4 `producto.json`; D5 `assets.json` + `checkout.json` + `tracking.json`; D6 `paquete.json`; D7 `campana.json`. El brief lleva `hash` (sin `hash` ni `aprobado_por`; es el que firma el dueño) y se define un `hash_contenido` calculado, no almacenado (`scripts.validar_esquemas.hash_contenido_brief`: sin `oferta_id`, `familia_id`, `creado_en`, `hash`, `aprobado_por`); `orq crear` busca ese `hash_contenido` en `ofertas/*/00-brief.yaml`: el mismo contenido devuelve el mismo `oferta_id`, contenido distinto asigna uno nuevo (idempotencia sin círculo). La campaña lleva `hash_config` (sin ese campo). `qa.artefacto_sha256` es el hash de `artefacto_ref` (archivo o carpeta, p. ej. `05-landing/sitio` = `destino.landing_hash`). Firmas humanas y sello de límites: **Ed25519** (`firma_humana.firma` y `limites.sello.firma` aceptan `ed25519:` o `hmac-sha256:`); la clave privada solo en el equipo del dueño y la verificación con la pública (C07, convenciones §5). HMAC se conserva para la oferta de ejemplo (clave de prueba no real) y para servicio a servicio. **Qué firma cada firma** (`scripts.validar_esquemas.payload_firma`, JSON canónico): `aprobacion` = `{oferta_id, etapa\|accion, hash_objetivo, object_ids ordenados, vigencia_hasta, aprobador, fecha}`; `sello` y `orden_firmada` = el objeto sin `firma`; exposición fiscal de `mercado` = `{oferta_id, paises, aprobador, fecha}`. El validador comprueba el **formato** de toda firma (`tipo_firma`, `problemas_firma`), exige Ed25519 con `FABRICA_ENTORNO=produccion` y verifica HMAC solo con clave de prueba; la verificación criptográfica de Ed25519 con la pública es de `engine.guard` (stdlib no la trae). Sin clave de verificación el validador avisa fuera de producción y **falla cerrado con `FABRICA_ENTORNO=produccion`**.

## 2. Tabla única de gates por etapa y nivel

## 3. Mapa de estados de `estado.json`

**Estado de etapa** (`etapas.<E>.estado`): `pendiente`, `en_progreso`, `en_QA`, `aprobado`, `bloqueado`, `escalado`. "Gate pendiente" es el indicador booleano `gate_pendiente` dentro de `en_QA`. Solo el motor escribe `estado.json`.

| De → a | Condición | Quién |
|---|---|---|
| pendiente → en_progreso | dependencias aprobadas y vigentes, sin `PAUSA`, límites OK | motor |
| en_progreso → en_QA | salida válida (esquema + invariantes) | motor |
| en_progreso → bloqueado | falta input o credencial, timeout, API caída | motor |
| en_QA → aprobado | PASS o PASS_CON_NOTAS y gate: A automático; S automático si PASS (humano si hay notas o por muestreo); H firma del dueño | motor / humano |
| en_QA → en_progreso | FAIL o MAYOR abierto y ronda < 2 | motor |
| en_QA → escalado | ronda 2 con BLOQUEANTE o MAYOR, ESCALAR, o veto de X1 | motor |
| bloqueado → en_progreso | causa resuelta | motor / humano |
| escalado → en_progreso / aprobado | orden humana; override firmado | humano |
| aprobado → pendiente | una entrada cambió (`obsoleta=true`; la versión previa se conserva) | motor |

Dependencias de aprobación: D1 ∅ · M1 ← D1 · D2 ← D1, M1 · D3 ← D2 · D4 ← D3 · D5 ← D3, D4 · D6 ← D3, D5 · D7 ← D5, D6 · D8 ← D7 · D9 ← D8 · D10 ← D4, D5. Una etapa aprobada exige `entradas[dep] == hash_salida` de cada dependencia aprobada (si no, está obsoleta).

**Fase de la oferta** (`fase`): `borrador → en_construccion → listo_para_activar → en_test → {validada | fallida | inconclusa}`; `inconclusa → en_test` (extender) · `validada → escalando` · `en_test | escalando → pausada → en_test | escalando` (reactivar = gate H) · cualquiera → `retirada`. Solo `retirada` es final; `fallida → en_construccion` admite reapertura firmada (gate H). Opcional `espera_madurez{activa, hasta}` en `estado.json`: tras cerrar la campaña el motor sigue leyendo sin gastar hasta `hasta` (último pedido considerado + política de reembolso + `veredicto.madurez_dias_extra`). `validada` solo sale del veredicto de D8 (definición única, sección 4, R11).

**Estado de la campaña** (`campana.estado`): `borrador → preflight_ok → aprobada → activa ↔ pausada → cerrada`. Meta crea en borrador; activar es una acción aparte con gate, hash de configuración aprobada y `object_ids` exactos. Con `estado != borrador` y límites incompletos, el validador sale con código 5.
